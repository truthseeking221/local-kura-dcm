# Receptionist

Story-level scenarios that show the **receptionist app experience** assembled
out of the kit's `atoms` / `molecules` / `organisms`. The story tree documents
the canonical visual contract for each step page — the app's data-wiring
shells (`apps/receptionist/src/{shell,wizard}/`) consume the same kit organisms
directly and are reviewed in the running app, not in Storybook.

## Reference

Visual + behavioural source of truth: [`design-receptionist.kura.med/patients`](https://design-receptionist.kura.med/patients).
Old source for shape and edge cases only: [`Kura-med/design`](https://github.com/Kura-med/design).

## Architectural rules followed

1. **Layer purity.** `<WizardStepBody>` is a molecule. It imports only `cn`. No upward imports. The wizard frame organism (`WizardLayout`) composes slots from outside.
2. **Generic primitives over module-specific compositions.** `<WizardStepBody>` is universal (no `@kuraModules` tag); reach via `@kura/ui-kit` or `@kura/ui-kit/molecules`. App data-wiring shells (`apps/receptionist/src/shell/*.tsx`, `apps/receptionist/src/wizard/*.tsx`) own the state-to-props wiring and live in the app — they are the correct factoring, not anti-pattern.
3. **No wrapper stories.** Storybook documents the kit's visual contract — kit organisms have their own stories (`Organisms/AppHeader`, `Organisms/AppSidebar`, `Organisms/SubjectHeader`, `Organisms/Stepper`, …). Per-step `Receptionist/Wizard/Steps/Step*` stories combine multiple kit organisms into realistic scenarios; they don't re-implement the app's shells.
4. **No new tokens, themes, or icon collections.** All chrome uses existing CSS variables and `<Icon name="tabler:..."/>` via `@iconify/react`.
5. **Source-only.** No build, no bundle. Edits in `src/` reload live in consumers.
6. **Mock data only.** Fixtures live in `_fixtures/patient.ts`. No API client, no state machine — each story renders a frozen configured state.

## What's covered

**Per-step canonical visuals** under `Receptionist/Wizard/Steps/` — full chrome (sidebar + header + stepper + step content + cart rail) for all 6 steps:

| Story | State |
|---|---|
| Step 1 — Blank walk-in | empty patient, capture-method picker (QR / NFC / Manual) |
| Step 1 — Identity captured | locked identity card with re-capture link |
| Step 2 — Patient | review card + contact channels + optional address/refund sections |
| Step 3 — Insurance · with policy | eligibility card + co-pay banner |
| Step 3 — Insurance · empty | direct-pay zero-state |
| Step 4 — Orders | catalog search + popular bundles + lab list |
| Step 5 — Pre & post consult | intake checklist workflow + post-consult scheduling calendar |
| Step 6 — Payment | payer + method radios + KHQR ready banner |

**Order Cart** — 4 stories: Default, Empty, Paid, PaidEditPending.

**Modals** — 3 stories: HotkeyCheatsheet, PaidEditPrompt, RecaptureConfirm.
